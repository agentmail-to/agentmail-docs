## Summary

A browser that signs in as an inbox at AgentID is now an API key, a public key scoped to that inbox, managed with the same list, get, and delete calls as every other API key. Start one with provider connect, or attach one to a sign-in the browser is already in, then poll it until the browser finishes, list it alongside your bearer keys, and revoke it when it is no longer needed, without handling key material or enrollment internals. A new connect call with no provider enrolls a browser and stops, so agents can prepare a browser profile ahead of any sign-in.

### What's new?

**New endpoints:**

- `POST /v0/providers/connect` - Connect a browser by provider domain, with no provider at all, or by attaching to the AgentID sign-in the browser is already on with `transaction_jti`. The no-provider mode returns a `magic_url` and the browser stops on AgentID once the session is active; attach mode returns no URL. Pass `authorize: true` to approve the relying party on the agent's behalf, in either mode.
- `GET /v0/api-keys/{api_key_id}` - Get one credential of any family. For a browser session, poll it to watch `status` go from `pending` to `active`.
- `PATCH /v0/api-keys/{api_key_id}` - Rename or re-permission a bearer key or a public-key credential.

**New features:**

- **One vocabulary for every credential family**: `GET /v0/api-keys` lists bearer keys by default and every public key with `type=public_key`, registered keys first and then browser keys, filterable by `inbox_id`. Every item carries `type`, `organization_id`, `pod_id`, `inbox_id`, `permissions`, `created_by`, and the timestamps; browser keys add `status`.
- **One handle for the whole lifecycle**: connect responses now carry `api_key_id`, the same ID Get, List, and Delete use before and after activation. `session_id` stays as a deprecated alias with the same value.
- **Delete covers every family**: `DELETE /v0/api-keys/{api_key_id}` deletes a bearer key, revokes a registered public key, cancels a pending browser session, or revokes an active one. Deleting a bearer key still revokes every browser session it authorized.
- **Public keys live under api-keys**: `POST /v0/api-keys` with a `public_key` body registers a public-key credential, and list, get, update, and delete cover it alongside bearer keys. The `/v0/api-keys/public-keys` routes are deprecated aliases.
- **Client IDs for public keys**: register a public key, or connect a browser, with a caller-chosen `client_id`, unique within the organization across every public key, and use it in place of `api_key_id` on get, rename, and revoke. Registration and connect are idempotent on the alias: a repeated connect answers from the key the `client_id` names instead of minting another. The `Idempotency-Key` header on connect is deprecated and read as `client_id` when the body omits it.

**Changes:**

- `GET /v0/api-keys/browser-credentials`, `DELETE /v0/api-keys/browser-credentials/{credential_id}`, `POST /v0/inboxes/{inbox_id}/browser-credentials/enrollments`, `DELETE /v0/api-keys/browser-credentials/enrollments/{enrollment_id}`, and the `/v0/api-keys/public-keys` list, register, rename, and revoke routes are deprecated in favor of the api-keys and connect endpoints above. All keep working.

### Use cases

Build agents that:

- Prepare a persistent browser profile as an inbox before any sign-in, then sign in silently at every AgentID relying party
- Drive a browser through a relying party's sign-in and complete the AgentID step with one API call
- Wait on a browser by polling one endpoint instead of diffing a list
- Audit and revoke every credential that can act as an inbox, bearer and browser alike, from one list

<CodeBlocks>
```python title="Python"
from agentmail import AgentMail

client = AgentMail(api_key="your-api-key")

# enroll a browser with no provider handoff (omit provider)
connect = client.providers.connect_browser(
    inbox_id="agent@example.com",
    request_options={"additional_headers": {"Idempotency-Key": "enroll-profile-1"}},
)
print(connect.magic_url)  # open in the browser that should hold the key

# poll until the browser finishes
key = client.api_keys.get(api_key_id=connect.api_key_id)
print(key.status)
```

```typescript title="TypeScript"
import { AgentMail } from "agentmail";

const client = new AgentMail({ apiKey: "your-api-key" });

// enroll a browser with no provider handoff (omit provider)
const connect = await client.providers.connectBrowser(
  { inboxId: "agent@example.com" },
  { idempotencyKey: "enroll-profile-1" },
);
console.log(connect.magicUrl); // open in the browser that should hold the key

// poll until the browser finishes
const key = await client.apiKeys.get(connect.apiKeyId);
console.log(key.status);
```
