## Summary

Authenticate webhook deliveries and route them through downstream services with custom HTTP headers managed by AgentMail. Header values remain write-only, so agents can rotate credentials without exposing them through read endpoints.

### What's new?

- Pass a non-empty `headers` map when creating organization-, pod-, or inbox-scoped webhooks.
- `GET /v0/webhooks/:webhook_id/headers` lists configured header names without returning their values.
- `PATCH /v0/webhooks/:webhook_id/headers` atomically sets or removes headers. Pod- and inbox-scoped variants are also available.
- Use `get_headers` and `update_headers` in Python, or `getHeaders` and `updateHeaders` in TypeScript.

### Use cases

Build agents that:

- Authenticate webhook deliveries to third-party APIs with bearer tokens or API keys
- Route events by tenant, environment, or workflow without changing the webhook payload
- Rotate webhook credentials without recreating endpoints or interrupting delivery

<CodeBlocks>
```python title="Python"
from agentmail import AgentMail

client = AgentMail(api_key="your-api-key")
webhook = client.webhooks.create(
    url="https://api.example.com/events",
    event_types=["message.received"],
    headers={"Authorization": "Bearer hook-secret"},
)
client.webhooks.update_headers(
    webhook.webhook_id, headers={"Authorization": "Bearer rotated-secret"}
)
```
```typescript title="TypeScript"
import { AgentMailClient } from "agentmail";

const client = new AgentMailClient({ apiKey: "your-api-key" });
const webhook = await client.webhooks.create({
  url: "https://api.example.com/events",
  eventTypes: ["message.received"],
  headers: { Authorization: "Bearer hook-secret" },
});
await client.webhooks.updateHeaders(webhook.webhookId, {
  headers: { Authorization: "Bearer rotated-secret" },
});
```
</CodeBlocks>
