## Summary

Signed CDN URLs for attachments, raw messages, and extracted attachment text now tell browsers to download files on direct navigation instead of rendering them as pages. This reduces the risk of executing sender-controlled content in a browser.

### What's new?

- The change covers attachment `download_url` values (including thread-level attachments), raw-message `.eml` `download_url` values, and extracted attachment `text_url` values.
- Responses enforce download disposition and add browser hardening headers: `nosniff`, frame denial, a restrictive content security policy with sandboxing, a no-referrer policy, and HSTS.
- File bytes, `content_type`, and `filename` metadata are unchanged. Existing filename parameters in download headers are preserved.
- Server-side fetches still work. Supported images, video, and audio can still load as subresources through `img`, `video`, and `audio` elements, including images referenced by CSS. Stylesheets remain subject to correct MIME types with `nosniff`; this is not a guarantee that arbitrary attachments can load as CSS.

### Breaking changes

⚠️ **Direct navigation and iframe previews change to downloads.**

Previously, opening one of these signed URLs in a browser tab or embedding it in an iframe could display the file. It now downloads instead, and iframe previews are blocked. Use a download link for this URL. If your application needs previews, fetch the bytes on your server and render only validated, supported file types through your own isolated preview flow; do not serve arbitrary HTML or SVG under your application origin.

Use the HTTPS URLs returned by the API without changing their scheme. Requests made over `http://` now receive `403 Forbidden` instead of an HTTPS redirect.

```html
<!-- before: embedding the attachment download URL -->
<iframe src="ATTACHMENT_DOWNLOAD_URL" title="Attachment preview"></iframe>

<!-- after: offering the attachment as a download -->
<a href="ATTACHMENT_DOWNLOAD_URL">Download attachment</a>
```

### Use cases

- Let users download incoming attachments for local inspection.
- Fetch attachment bytes in an agent's backend for document processing.
