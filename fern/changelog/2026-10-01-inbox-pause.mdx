## Summary

The API reference now documents pausing an inbox. The API already supported it: set an inbox's `status` to `paused` to stop it sending and receiving mail without deleting it, and set it back to `active` to resume.

### What's new?

- `status` on `PATCH /v0/inboxes/{inbox_id}` and `POST /v0/inboxes`, and on the pod routes for the same operations. Values are `paused` and `active`.
- Inbox responses include `status: "paused"` while an inbox is paused. An active inbox has no `status` field.
- Sends from a paused inbox return `403` with code `inbox_paused`. Scheduled drafts that come due while it is paused fail and are not retried on resume.
- Mail sent to a paused inbox is dropped without a bounce and is not delivered when the inbox is resumed.

### Use cases

- Build agents that stop an inbox from acting on its own while a human reviews it.
- Take an inbox out of service without giving up its address, then bring it back later.

<CodeBlocks>
```python title="Python"
from agentmail import AgentMail

client = AgentMail(api_key="your-api-key")

# pause, then resume
client.inboxes.update(inbox_id="support-agent@agentmail.to", status="paused")
client.inboxes.update(inbox_id="support-agent@agentmail.to", status="active")
```
```typescript title="TypeScript"
import { AgentMailClient } from "agentmail";

const client = new AgentMailClient({ apiKey: "your-api-key" });

// pause, then resume
await client.inboxes.update("support-agent@agentmail.to", { status: "paused" });
await client.inboxes.update("support-agent@agentmail.to", { status: "active" });
```
</CodeBlocks>
