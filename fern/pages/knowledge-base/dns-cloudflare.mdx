## Steps

1. Log in to the [Cloudflare dashboard](https://dash.cloudflare.com)
2. Select your domain
3. Go to **DNS**, then click **Records**
4. Click **Add Record** for each record AgentMail requires

## Adding the TXT records (SPF, DKIM, DMARC)

Add one TXT record for each row below:

| Record | Name | Content |
| --- | --- | --- |
| SPF | `mail` | The SPF value from AgentMail |
| DKIM | The DKIM selector host from AgentMail (e.g., `selector._domainkey`) | The DKIM value from AgentMail |
| DMARC | `_dmarc` | The DMARC value from AgentMail |

Set **Type** to `TXT` and **TTL** to `Auto` for each one.

Cloudflare automatically strips your domain from the Name field. Enter only the host portion (e.g., `selector._domainkey`), not the full `selector._domainkey.yourdomain.com`.

<Warning>
Do **not** add anything to an existing SPF record on your root domain (`@`). AgentMail's SPF record goes on the `mail` host, which is a different hostname, so your existing SPF for Google Workspace or another service stays exactly as it is.
</Warning>

<Note>
Legacy orgs should keep existing working DNS records in place. For new domain setup, add the TXT selector records shown in AgentMail.
</Note>

## Adding the MX records (receiving and bounces)

Add one MX record for each row below:

| Record | Name | Mail server | Priority |
| --- | --- | --- | --- |
| Receiving | `@` | The receiving MX value from AgentMail | `10` |
| Bounces (MAIL FROM) | `mail` | The `feedback-smtp` MX value from AgentMail | `10` |

Set **TTL** to `Auto`. Skip the receiving MX if you created the domain as send-only (`inbound_enabled: false`). The `mail` MX must be the only MX record on the `mail` host.

If you registered a subdomain such as `agents.yourdomain.com` to avoid conflicts with your existing email provider, add the subdomain to every name: `agents`, `mail.agents`, `_dmarc.agents`, and `selector._domainkey.agents`.

## Verification

After adding all records, go back to the [AgentMail Console](https://console.agentmail.to) and click **Verify Domain**.

Cloudflare DNS typically propagates within **1 to 5 minutes**, making it one of the fastest providers for DNS updates.

## Common Cloudflare Issues

- **Existing SPF record on your root domain:** Leave it unchanged. Do not add `include:agentmail.to` or any other AgentMail value to it. If an earlier guide told you to add `include:agentmail.to`, remove that mechanism: `agentmail.to` publishes no SPF record, so the include causes an SPF permanent error.

- **Duplicate TXT values:** Cloudflare lets you add TXT records with the same name, but duplicate SPF or stale DKIM selector records can make verification fail. Keep only the current values AgentMail provides for each host.

- **Name field auto-strips domain:** Cloudflare removes the domain portion from the Name field automatically. If your DKIM selector is `selector._domainkey`, enter just that. Do not enter `selector._domainkey.yourdomain.com`, or the record will be created incorrectly.
