Pods provide tenant isolation for multi-tenant applications. Each Pod is an isolated workspace containing its own inboxes, domains, threads, and drafts, completely separated from other Pods.

## When to use Pods

Pods are designed for scenarios where you need to keep different customers' or agents' email data separate:

- **SaaS platforms** where each customer's agents need their own email inboxes
- **Agency setups** where each client gets isolated email infrastructure
- **AI agent platforms** where different agents need dedicated, isolated workspaces
- **White-label products** where end users get email under their own brand

If you are only managing email for your own organization, Pods are optional. You can work directly with inboxes without creating them.

## The hierarchy

```
Organization (your business)
    └── Pod (Customer A)
        ├── Inbox: support@customera.com
        ├── Inbox: sales@customera.com
        └── Domain: customera.com
    └── Pod (Customer B)
        ├── Inbox: hello@customerb.com
        └── Domain: customerb.com
```

Everything inside a Pod is isolated. Customer A cannot see Customer B's emails, threads, or drafts.

## Creating a Pod and its resources

An inbox on a custom domain such as `acme.com` can only be created once that domain is registered in your organization or in the Pod, and verified. So the order is: create the Pod, add the customer's domain to it, publish the DNS records it returns, wait for the domain to verify, then create inboxes.

<CodeBlocks>
```python title="Python"
import os
import time

from agentmail import AgentMail

client = AgentMail(api_key=os.getenv("AGENTMAIL_API_KEY"))

# create a pod for the customer, keyed by your internal customer id
pod = client.pods.create(name="Acme Corp", client_id="customer_12345")

# register the customer's domain in the pod
domain = client.pods.domains.create(pod_id=pod.pod_id, domain="acme.com")

# publish these records at the customer's dns provider
for record in domain.records:
    print(record.type, record.name, record.value, record.priority or "")

# wait until agentmail has verified the records
while client.pods.domains.get(pod_id=pod.pod_id, domain_id=domain.domain_id).status != "VERIFIED":
    time.sleep(60)

# create inboxes on the verified domain
support_inbox = client.pods.inboxes.create(
    pod_id=pod.pod_id,
    username="support",
    domain="acme.com",
    display_name="Acme Support"
)

sales_inbox = client.pods.inboxes.create(
    pod_id=pod.pod_id,
    username="sales",
    domain="acme.com",
    display_name="Acme Sales"
)
```

```typescript title="TypeScript"
import { AgentMailClient } from "agentmail";

const client = new AgentMailClient({ apiKey: process.env.AGENTMAIL_API_KEY });

// create a pod for the customer, keyed by your internal customer id
const pod = await client.pods.create({ name: "Acme Corp", clientId: "customer_12345" });

// register the customer's domain in the pod
const domain = await client.pods.domains.create(pod.podId, { domain: "acme.com" });

// publish these records at the customer's dns provider
for (const record of domain.records) {
  console.log(record.type, record.name, record.value, record.priority ?? "");
}

// wait until agentmail has verified the records
while ((await client.pods.domains.get(pod.podId, domain.domainId)).status !== "VERIFIED") {
  await new Promise((resolve) => setTimeout(resolve, 60_000));
}

// create inboxes on the verified domain
const supportInbox = await client.pods.inboxes.create(pod.podId, {
  username: "support",
  domain: "acme.com",
  displayName: "Acme Support",
});

const salesInbox = await client.pods.inboxes.create(pod.podId, {
  username: "sales",
  domain: "acme.com",
  displayName: "Acme Sales",
});
```
</CodeBlocks>

DNS changes can take from a few minutes to 48 hours to propagate. Instead of polling, you can subscribe to the [`domain.verified` event](https://docs.agentmail.to/events). See the [custom domains guide](https://docs.agentmail.to/custom-domains) for the records and verification statuses. Creating an inbox on a domain that is not verified yet fails, and so does creating one on a domain that belongs to a different Pod.

If you do not need a custom domain, omit `domain` and the inbox is created on `agentmail.to`.

<Note>
Use the `client_id` parameter when creating a Pod to set your own unique identifier, as in the example above. This way you can map Pods to your internal customer IDs without maintaining a separate mapping table, and retrying the create returns the same Pod instead of a duplicate.
</Note>

## Listing resources within a Pod

You can list inboxes, threads, drafts, and domains scoped to a specific Pod:

```python title="Python"
# list inboxes in a pod
inboxes = client.pods.inboxes.list(pod_id=pod.pod_id)

# list threads across all inboxes in a pod
threads = client.pods.threads.list(pod_id=pod.pod_id)

# list drafts in a pod
drafts = client.pods.drafts.list(pod_id=pod.pod_id)
```

This makes it easy to build features like "show all unread emails for Customer X" or "list all pending drafts for Customer Y."

## Deleting a Pod

You cannot delete a Pod that still has inboxes, domains, or Pod-scoped API keys, and you cannot delete an inbox that still has inbox-scoped API keys. Clean up those child resources first:

<CodeBlocks>
```python title="Python"
# each list call returns one page; follow next_page_token if a pod has more

# delete each inbox, after any api keys scoped to it
for inbox in client.pods.inboxes.list(pod_id=pod.pod_id).inboxes:
    for key in client.inboxes.api_keys.list(inbox_id=inbox.inbox_id).api_keys:
        client.inboxes.api_keys.delete(inbox_id=inbox.inbox_id, api_key_id=key.api_key_id)
    client.pods.inboxes.delete(pod_id=pod.pod_id, inbox_id=inbox.inbox_id)

# delete the pod's domains
for domain in client.pods.domains.list(pod_id=pod.pod_id).domains:
    client.pods.domains.delete(pod_id=pod.pod_id, domain_id=domain.domain_id)

# delete api keys scoped to the pod
for key in client.pods.api_keys.list(pod_id=pod.pod_id).api_keys:
    client.pods.api_keys.delete(pod_id=pod.pod_id, api_key_id=key.api_key_id)

# then delete the pod
client.pods.delete(pod_id=pod.pod_id)
```

```typescript title="TypeScript"
// each list call returns one page; follow nextPageToken if a pod has more

// delete each inbox, after any api keys scoped to it
for (const inbox of (await client.pods.inboxes.list(pod.podId)).inboxes) {
  for (const key of (await client.inboxes.apiKeys.list(inbox.inboxId)).apiKeys) {
    await client.inboxes.apiKeys.delete(inbox.inboxId, key.apiKeyId);
  }
  await client.pods.inboxes.delete(pod.podId, inbox.inboxId);
}

// delete the pod's domains
for (const domain of (await client.pods.domains.list(pod.podId)).domains) {
  await client.pods.domains.delete(pod.podId, domain.domainId);
}

// delete api keys scoped to the pod
for (const key of (await client.pods.apiKeys.list(pod.podId)).apiKeys) {
  await client.pods.apiKeys.delete(pod.podId, key.apiKeyId);
}

// then delete the pod
await client.pods.delete(pod.podId);
```
</CodeBlocks>

<Warning>
When you delete an inbox, all associated messages, threads, and drafts are automatically cleaned up. You do not need to delete them individually.
</Warning>

## Things to know

- **Cross-pod email works normally.** Inboxes in different Pods can send and receive emails from each other, just like any other email addresses. Pods isolate data access, not email delivery.
- **Inboxes cannot move between Pods.** If you need to reassign an inbox, create a new one in the target Pod.
- **Pod-scoped API keys.** You can create API keys scoped to a specific Pod, so each tenant only has access to their own resources. Create them via `POST /pods/{pod_id}/api-keys`.
- **Inbox-scoped API keys.** For even finer control, you can create keys scoped to a single inbox. These keys can only access that inbox's threads, messages, and drafts. Create them via `POST /inboxes/{inbox_id}/api-keys`.
- **No limit on Pods.** You can create as many Pods as you need for your customers.
- **Domains can be scoped to one Pod or all Pods.** A domain cannot be shared across a subset of Pods.

For more details, see the [Pods core concept](https://docs.agentmail.to/documentation/core-concepts/pods) documentation.
