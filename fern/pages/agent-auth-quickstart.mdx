An agent can authenticate with AgentMail in four ways. It can sign itself up and get its own API key, use a key its human created, use the CLI, or connect to the hosted MCP server. A machine-readable version of this page is at [agentmail.to/auth.md](https://www.agentmail.to/auth.md).

## Get a key yourself (no human needed)

Call `POST /v0/agent/sign-up` with a `username` and the owner's `human_email`. The response contains the API key. It is returned once and cannot be recovered, so store it right away.

```bash
curl -X POST https://api.agentmail.to/v0/agent/sign-up \
  -H "Content-Type: application/json" \
  -d '{"username": "my-agent", "human_email": "owner@example.com"}'
```

Until the owner verifies, the agent can send only to the owner, up to 10 emails a day. AgentMail emails the owner a 6 digit code. The agent submits it to `POST /v0/agent/verify` with `otp_code`:

```bash
curl -X POST https://api.agentmail.to/v0/agent/verify \
  -H "Authorization: Bearer $AGENTMAIL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"otp_code": "123456"}'
```

If you leave out `human_email`, the agent gets a receive-only inbox. Add the owner later with `POST /v0/agent/human`, and AgentMail sends them the code.

See the [Sign Up reference](/api-reference/agent/sign-up) for every field, and [Why can my agent only email its human?](/knowledge-base/agent-sign-up-limits) for the full limits before and after verification.

## Use a key a human gave you

Send the key as a bearer token:

```bash
curl https://api.agentmail.to/v0/inboxes \
  -H "Authorization: Bearer $AGENTMAIL_API_KEY"
```

The SDKs read `AGENTMAIL_API_KEY` from the environment automatically:

```bash
pip install agentmail   # Python
npm install agentmail   # TypeScript
```

Keep the key in an environment variable or a secret store. Never paste API keys into chat. To give an agent only the access it needs, create a scoped key with [Permissions](/permissions).

## CLI

The AgentMail CLI reads the same `AGENTMAIL_API_KEY` and can run the sign-up and verify steps for you. See [CLI](/integrations/cli).

## MCP

Connect your MCP client to `https://mcp.agentmail.to/mcp`. Clients that support MCP OAuth sign in without handling a key. See [MCP](/integrations/mcp) for each client's setup.

## Testing

No sandbox address needed. Every new agent account can already email its owner, so you test against a real inbox you control, with real delivery, from the first minute. Once the owner verifies, you can send to anyone.
